## 1. 盘参考站（https://github.com/shuishui313/knowledge-base）

本站是新站，没有旧版，所以拿参考站来盘。我把仓库克隆下来逐个看过：`README.md`、`AGENTS.md`、`docs/decisions.md`、`docs/declined.md`、`notes/*`、`site/`（Astro）和 `.github/workflows/pages.yml`。

参考站的基本情况：
- 内容按分区放在 `notes/<分区>/`。每个分区有一份 `README.md` 当中文目录表。
- 每篇的格式是「文首元数据行 + 固定顺序的小节」。
- 站点在 `site/` 目录，用 Astro。构建时读 Markdown 生成静态页。
- `pages.yml` 在推送到 main 时触发，用官方的 `upload-pages-artifact` 和 `deploy-pages` 部署。
- 首页是深色首屏，带一张随滚动移动的仪器图（`home-motion.ts`），下面三张等宽的路径卡片。没有搜索。

### 1.1 保留（照学）
| 项 | 参考站的做法 | 理由 |
|---|---|---|
| 分区归档 | `notes/<分区>/` 一个分区一个目录 | 我们 6 类正好一类一个目录，人和机器都好找 |
| 每篇统一结构 | 文首元数据 + 固定小节顺序 | 6 个 bot 格式不一样，统一外壳后列表页和搜索才能做 |
| Markdown 是唯一的源 | 「网页不改写课文」 | 推送原文就是证据，网页只负责排版，不改内容 |
| 文件名带日期和稳定编号 | `FDE-NN-YYYY-MM-DD-…`，编号不复用 | 看文件名就知道哪天哪篇，链接不会失效 |
| Astro 构建 + Actions 部署 | `site/` + `pages.yml`（官方 deploy-pages） | 已经被证明能跑通。静态站没有服务器要维护 |
| 构建后自检 | `scripts/verify-dist.mjs` | 我们用它查「6 类都在、每页都有页脚免责」 |
| 404 页 | 有 404，带「回到首页」主按钮 | 保留这个结构，改成我们的文案 |
| 不放内部资料 | README 写明「不涉及任何机构的内部资料」 | 和我们的合规要求一致，而且我们写得更严（见第 9 节） |

### 1.2 改（我们的做法不同）
| 项 | 参考站 | 我们 | 理由 |
|---|---|---|---|
| 首页 | 深色首屏 + 仪器图 + 3 张等宽卡片 | 白底，顶部搜索框，下面 6 类卡片（每类最新几篇） | 规范禁止大面积黑色头图和「居中主视觉 + 3 张等大卡片」。简报要求首页有搜索和每类最新几篇 |
| 搜索 | 没有 | Pagefind 离线全文搜索，支持中文分词 | 简报验收写了「搜索能用」 |
| 顶部导航 | 深色、半透明毛玻璃（`rgba(12,13,16,.92)` + blur） | 白底，一行，底部一条细线，不吸顶 | 规范禁止深色工具栏。v3 11.6-4 要求吸顶栏不超过屏高 12%，我们干脆不吸顶 |
| 动效 | 首页仪器图随滚动移动，卡片进入视野时揭示 | 没有动效，只保留链接和按钮的颜色变化 | 简报要求无花哨动效。v3 11.7-4 默认静态 |
| 目录页 | 每个分区手写 `README.md` 表格 | 列表页由构建时扫描 front matter 自动生成，按日期倒序 | 每天有多篇自动入库，手写目录一定会漏 |
| 元数据写法 | 文首一行粗体文字（`**FDE-01** · **2026-11-02** …`） | YAML front matter，构建时校验 | 机器入库需要能校验的字段 |
| 内容目录名 | `notes/` | `content/`（不用 `docs/`） | `docs/` 容易被误以为是 Pages 的「从 /docs 发布」模式。我们走 Actions 发布 |
| 双语 | `README.md` 和 `README.en.md` 各一份 | 只做中文 | 简报只要中文，内容源也是中文 |
| 字体 | 下载 Inter 网络字体 | 用系统字体栈，不下载中文网络字体 | 中文字体文件太大会拖慢首屏。苹方、思源、微软雅黑系统都自带 |

### 1.3 不要
| 项 | 理由 |
|---|---|
| 首页深色首屏和 SVG 仪器图 | 违反规范第 7 节（大面积黑色头图），而且和内容没关系 |
| 滚动驱动动效（`home-motion.ts`） | 简报要求无花哨动效 |
| 难度、面试频率这类小芯片 | 我们的内容没有这些字段。规范第 7 节也禁止标题小徽章 |
| 「下一篇预告」「自测题 + 参考答案」 | 那是课程体例，我们只归档推送 |
| KaTeX、Mermaid 依赖 | 推送里没有公式和流程图，少一个依赖就少一个出错点 |
| 中英文双 README | 不需要 |

### 6.2 正文
正文是推送原文，原样放进来，不改写。网页统一套一个外壳，从上到下：
1. 面包屑：首页 / 分类名
2. H1：标题
3. 元信息一行（0.875rem，#666666）：日期 · 时点 · 来源 bot（· 数据截至 as_of）

## 7. 页面线框说明（按推荐方向 A；方向确认后再细化）

### 通用规则（每页都适用）
- 颜色：背景 #FFFFFF，文字 #111111，次要文字 #666666。腾讯蓝 #0052D9 只用在主按钮和带 `aria-current="page"` 的当前链接上。只做浅色，`:root { color-scheme: light }`。
- 边框和阴影（规范只写「细边框加极淡阴影」，具体色值由本方案定，对比度都算过）：
  - 展示卡片和分隔线：1px #E5E5E5（纯展示，规范允许用浅色）
  - 可交互控件（搜索框、次按钮）：1px #8C8C8C，对白 3.36:1，满足 v3 第 6 节 ≥3:1
  - 卡片阴影：`0 1px 2px rgba(17,17,17,.04)`，只此一种，不加深
- 字号（v4 第 3 节）：常规六档 0.75 / 0.875 / 1 / 1.25 / 1.75 / 2.25rem 用于正文、导航、按钮、标签、列表、页脚；展示档只用于首页 H1、副标题、分类名、分类说明（1280：3.5 / 1.75 / 2.5 / 1.3125rem；390 和 320：2 / 1.1875 / 2 / 1.1875rem）。H1 和分类名行高 1.2。不在 `html` 上写死根字号。
- 间距只用 4 / 8 / 16 / 24 / 32 / 48 / 64 / 96px（v4 第 4 节，写成 CSS 变量）。每个 margin / padding / gap 只写一个档位值，不靠相邻几段叠出档外的距离。水平居中用 `margin-inline:auto`，算出来的值不是间距档，不算违规。圆角：按钮 8px，输入框 8px（v4 第 5 节），卡片 12px。
- 普通链接：墨色加下划线。悬停时加粗下划线，不改颜色，不只靠颜色区分。当前链接用腾讯蓝，再加 600 字重。
- 焦点框用浏览器自带的，不写 `outline: none`（v3 11.2-5）。
- 可点区域至少 24×24px，390 档至少 44×44px。「查看全部」这类链接用内边距撑高度。
- 没有动画，只保留颜色和下划线的变化。
- 加载态用原生 `<progress>`（不写 value）加一句文字说明，不用转圈图标，不用渐变。报错态用 `role="alert"` 加文字。空态写一句说明，再给一个能点的出路。
- 页面骨架：`lang="zh-CN"`；英文站名「Cathy's Knowledge Base」所在元素（顶栏站名、首页 H1）加 `lang="en"`，读屏按英文读、浏览器按英文断词；每页一个 `<main>`、一个 H1，有「跳到正文」链接，`<title>` 格式是「页面主题 | Cathy's Knowledge Base」（v3 11.1）。
- 320px 和文字放大 200%（v3 第 8 节）：所有布局用 `gap` 加自动换行的网格，文字容器不写死高度，标题不截断，长网址可以折行（`overflow-wrap: anywhere`），不用 `100vw`。

### 7.0 手机端怎么用（Cathy 要求：手机上能正常浏览，不是电脑版缩小）
手机是重点使用场景之一（比如通勤时翻当天推送）。下面这些是专门为手机做的安排，在 390px 和 320px 下生效，不只是把 1280 的版面等比缩小。
- **基础**：每页写 `<meta name="viewport" content="width=device-width, initial-scale=1">`，不禁止双指缩放。正文 1rem（16px），手机上不再缩小，保证不用放大就能读。外边距 16px。
- **搜索（手机第一件事）**：搜索框在首页标题下面，打开就能点到，不用滚动。输入框用 `type="search"`、`enterkeyhint="search"`，手机键盘右下角显示「搜索」键；用表单原生提交，中文输入法选字时按回车不会误提交。输入框和按钮最小高度 48px（`min-block-size`，不写死高度）。搜索结果页里，分类筛选折成多行的大点击区（每项至少 44px 高），结果单栏排列，标题在上、分类和日期在下。
- **分类卡片**：手机上 6 张卡片排一列，按固定顺序（资本管理知识点、市场简报、新闻板块影响、2835 成分股、港股新股、AI 情报）。每张卡仍显示最新 3 篇。点法（和第 3 节、第 11 节第 7 条统一）：卡片本身不做成一整个链接；分类名（`<h3>` 里的链接，最小高度 44px）、「查看全部」（最小高度 44px）、每篇文章各是一个链接；**文章行整行可点**（最小高度 48px），不用精确点到标题文字。
- **快速跳到分类**：**Cathy 已答「要加」**（派 20:36 转达），两版 390 稿都已补画。位置在搜索框下面：先是一行小字「快速跳到分类」（0.875rem 灰），下面是 6 个分类文字链接（1rem，墨色加下划线），自动折行，不横向滑动。每个链接最小高度 44px（实测 44px）。外面包 `<nav aria-label="快速跳到分类">`，无障碍名称和可见小标题完全一样（评审 v2 第 9 条）；名字里不写「导航」，也不和列表页的「分类」nav 重名。
  6 个链接都去各分类列表页 `/<slug>/`，和卡片里同名的分类名链接去同一个地址（同名同去向，评审 v2 第 8 条）：
  | 链接文字 | 去向 |
  |---|---|
  | 资本管理知识点 | `/cm-knowledge/` |
  | 市场简报 | `/market-brief/` |
  | 新闻板块影响 | `/news-impact/` |
  | 2835 成分股 | `/etf-2835/` |
  | 港股新股 | `/hk-ipo/` |
  | AI 情报 | `/ai-intel/` |
  **C-008 已定：手机顶栏没有「分类」链接，手机上去分类只靠「快速跳到分类」和下面的分类卡片**；电脑版顶栏保留「分类」（跳本页 `#cats`）。「快速跳到分类」只在手机宽度（≤40em）显示，1280 隐藏。定稿实测（只调间距，没改字号）：320×568 下搜索框底边 448px，390×844 下 385px，都不用滚动就能看到整个搜索框（之前版 2 在 320 下是 587px）。
- **分类列表页**：日期和时点一行、标题一行、摘要一行，上下排，不挤在同一行；整条可点。顶部分类切换链接自动折行，不做横向滚动。
- **文章页**：正文单栏，左右各 16px；行高 1.75，段落之间 16px。2835 成分股、涨跌榜、港股新股这类表格在手机上变成「每行一张小卡」，每格前面带列名，整页不出现横向滚动。页脚免责声明「仅个人学习笔记，不构成投资建议」字号和首页一致，0.75rem（是否够显眼「待确认」，合规审查定），手机上同样显示，不折叠、不隐藏。
- **不做的事**：不用汉堡菜单（总共只有 6 个分类，直接摆出来更快）；顶栏不吸顶，不随滚动隐藏；不弹窗、不弹「添加到主屏幕」提示；不用左右滑动切换分类。
- **验收（手机部分）**：390 和 320 宽下，首页不滚动就能看到搜索框；所有可点区域至少 44×44px；任何页面都没有横向滚动；文字放大到 200% 后内容不丢、不截断；手机键盘弹出时搜索框不被遮住；免责声明每页都在。

## 9. 合规与入库规则（写进 README 和 CONTRIBUTING）

1. 不放：客户姓名、客户账户、持仓（包括 Cathy 本人的）、交易指令、内部资料、未公开研报、内幕信息、公司内部系统截图和链接。

3. 图片默认不收。确实要收的，必须是有公开授权、和内容相符的图（规范第 7 节）。
4. 公开仓库的提交历史永久公开。所以**先检查再提交**，不能「先推上去再删」。
5. `check-content` 构建前做格式检查，再按关键词清单挡一遍（清单内容待合规审查给）。挡住了构建就失败，人工处理。

## 10. 技术栈比较与推荐

| | Astro + Pagefind（推荐） | MkDocs Material（或继任者 Zensical） | VitePress | Jekyll（Pages 原生） |
|---|---|---|---|---|
| 搭建难度 | 中：要写几个页面模板 | 低：配置文件就能出站 | 中 | 低 |
| 首页「每类最新几篇」 | 自己写，完全可控 | 要覆盖主题模板 | 要自定义布局（默认首页是居中大标题 + 特性卡片，正好是禁用版式） | 要写 Liquid 模板 |
| 符合规范的成本 | 低：样式从零写，只用规范的六档字号和颜色 | **高**：主题自带很多规范外的字号、颜色、彩色顶栏和圆角，要逐项覆盖，QA 抽查计算样式时容易漏 | 中：默认主题有自己的字号和颜色变量 | 中 |
| 中文离线搜索 | Pagefind 扩展版构建时按中文分词，浏览器端用 `Intl.Segmenter` 切分查询（v1.5.0 起） | 内置搜索，中文分词需要额外配置（具体做法未核实，选它时再查） | 内置 minisearch，中文要自己配分词 | 没有内置，要接第三方，中文弱 |
| 维护状态 | 活跃 | Material 已进入维护期，**2027-05-05 停止维护**，官方让迁到 Zensical（0.1.0，还很早期） | 活跃 | 活跃，但 Pages 内置的版本很旧 |
| 和参考站一致 | 一致（参考站就是 Astro） | 不一致 | 不一致 | 不一致 |

**推荐 Astro + Pagefind + GitHub Actions**。理由：
1. 规范很严，六档字号、四种颜色都要被 QA 抽查。从零写样式最容易做到 100% 合规，用现成主题反而要花更多时间覆盖。
2. Pagefind 是目前静态站里中文离线搜索最省事的方案：构建时分好词，查询时浏览器再分一次，不用服务器，不用另装分词库。
3. Astro 的 content collections 可以按 schema 校验 front matter。bot 自动入库时字段写错，构建直接失败，坏内容上不了线。
4. 和参考站同一套，`pages.yml` 可以直接照抄。

**中文搜索的已知局限**（如实写）：Pagefind 按「词」匹配，不按「任意子串」匹配。搜「一段」能找到「一段简单」，搜「段简」找不到。可以接受，搜索页的空态会提示换个词。

## 12. 逐页验收标准（设计评审看方案和截图，QA 实测）

**全站通用（每页都查）**
1. 计算样式里的颜色只有 #FFFFFF / #111111 / #666666 / #0052D9，加上本方案定的边框色 #E5E5E5、#8C8C8C 和阴影 rgba(17,17,17,.04)。腾讯蓝只出现在主按钮背景和 `aria-current="page"` 的链接上。
